# 폰 홈 화면 설치 확인 절차

> ⚠️ **신뢰된 사설 네트워크(집 Wi-Fi 등)에서만 진행한다. 카페·회사 등 공용 Wi-Fi에서는 절대 열지 말 것.**
> 이 앱은 현재 인증이 없다(계정/인증은 non-goal). LAN에 열어두면 같은 네트워크의 누구나
> 노트를 읽고/쓰고 LLM 호출(비용 발생)까지 할 수 있다. 확인이 끝나면 즉시 dev 서버를 끈다.

## 사전 조건

- 개발 머신과 폰이 같은(신뢰된) Wi-Fi에 연결돼 있을 것
- 개발 머신 LAN IP 확인: `ipconfig getifaddr en0` (Wi-Fi가 다른 인터페이스면 `en1` 등으로 교체)
- macOS 방화벽이 Node 연결을 막으면 최초 1회 허용 팝업이 뜬다 — 허용

## 기동 절차

1. 백엔드: `cd backend && npm run dev` (포트 3000)
2. 프론트: `cd frontend && npm run dev` (vite `server.host: true`로 LAN 바인딩됨, 포트 5173)
3. 터미널에 출력된 `Network:` 주소(`http://<LAN-IP>:5173`)를 폰 브라우저에 입력

## Android (Chrome) 절차

1. 위 주소로 접속
2. 우측 상단 메뉴(⋮) → "앱 설치" 또는 주소창의 설치 아이콘 탭
3. 확인 사항
   - [ ] 홈 화면에 아이콘(플레이스홀더 "R" 모노그램)이 표시되는가
   - [ ] 앱 이름이 "recall"(short_name)로 표시되는가
   - [ ] 아이콘 탭 시 주소창 없는 standalone 모드로 열리는가
   - [ ] 상단 상태바/스플래시 배경색이 테마색(#111827)과 맞는가

## iOS (Safari) 절차

1. 위 주소로 접속
2. 공유 버튼(□↑) → "홈 화면에 추가"
3. 확인 사항
   - [ ] 홈 화면에 아이콘이 표시되는가
   - [ ] 앱 이름이 표시되는가
   - [ ] 실행 시 Safari UI 없이 standalone으로 열리는가

## 알려진 제약 — 서비스워커는 LAN에서 검증되지 않을 수 있다

서비스워커는 "보안 컨텍스트"(HTTPS 또는 `localhost`)에서만 등록된다. 위 절차의
`http://<LAN-IP>:5173`는 평문 HTTP이므로 **서비스워커가 등록되지 않는 것이 정상**이다.
Android Chrome의 "앱 설치" 자체는 SW 없이도 매니페스트만으로 가능한 경우가 많지만,
설치 프롬프트 세부 조건은 브라우저 버전에 따라 달라질 수 있다.

서비스워커(오프라인 셸 캐시) 동작 자체를 확인하려면 개발 머신에서 직접:

1. `http://localhost:5173` 접속 (localhost는 보안 컨텍스트로 취급됨)
2. DevTools → Application → Service Workers에서 등록 상태 확인
3. Network 탭에서 오프라인 체크 후 새로고침 → 앱 셸(빈 화면 아님)이 뜨는지 확인
   - 단, 노트 목록/문제 생성 등 API 호출이 필요한 화면은 오프라인에서 정상적으로 에러가
     나야 한다(기능은 온라인 전제이며 API 응답을 캐시하지 않는다 — 의도된 동작).

LAN(폰)에서의 완전한 오프라인 셸 캐시 검증은 실제 HTTPS 배포 시점에 재수행한다.
